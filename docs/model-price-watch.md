# モデル単価表の定期チェック（#497）

`src/lib/ai-app-usage/models.ts` のモデル一覧・単価は、コード内の固定値のまま手で保守する。
その更新漏れ（新モデルの公開・価格変更）に気づくため、公式の料金ページを定期的に確認し、
**更新候補**として単価表（右上メニューの「モデル単価表」。#561でAI利用タブから移した）に出す。**候補を単価表へ自動では反映しない。**

## 仕組み

- **実行はVPSのプロセス内タイマー**（`src/instrumentation.ts` → `src/lib/ai-app-usage/price-watch/run.ts`）。
  60秒ごとに「予定時刻を過ぎて未実行か」だけを見て、実際の取得は週1回。画面を開いていなくても動く。
  PM2は fork モード1プロセスなので、プロセス内タイマーで足りる（複数プロセスにしたら成り立たない）。
  停止中に予定時刻を過ぎていたら、起動後すぐに実行する。
- **スケジュールの設定**（`.env`。未設定は既定）
  | 環境変数 | 既定 | 意味 |
  | --- | --- | --- |
  | `MODEL_PRICE_WATCH_DAY` | `1` | 曜日（0=日 … 6=土） |
  | `MODEL_PRICE_WATCH_HOUR` | `5` | 時（0〜23） |
  | `MODEL_PRICE_WATCH_TZ` | `Asia/Tokyo` | タイムゾーン |
  | `MODEL_PRICE_WATCH_ENABLED` | 本番のみ | `1` で本番以外でも実行、`0` で停止 |
  | `MODEL_PRICE_WATCH_PATH` | `.data/model-price-watch.json` | 状態ファイル |
  不正な値は既定へ戻る。変更後はアプリの再起動が必要。
- **全体または一部が失敗した回は、同じ予定時刻のうちに6時間あけて最大3回までやり直す。**
- 結果は `.data/model-price-watch.json`（最新の候補・実行履歴52件・通知済みの差分）。`GET /api/model-price-watch`
  （ログインセッションのみ）が保存済みの結果を返し、画面を開いても公式ページへは取りにいかない。

## 手動更新（#561）

単価表のモーダルの「更新して確認」は `POST /api/model-price-watch`（セッション＋CSRFヘッダ）で、公式ページを今すぐ確認する。

- **予定時刻と試行回数（`slot`）を進めない**（`RunOptions.manual`）。進めると手動の連打・失敗が定期のやり直し（6時間おき・最大3回）を
  削り、手動の成功で定期がその週を実行済みと見なす。`lastRun`・候補・履歴は更新する
- 直近の実行（成功・失敗とも）の完了から60秒以内は実行せず、保存済みの結果を `throttled: true` で返す。同時押しは相乗りで1回
- 応答は `GET` と同じ `PriceWatchView`。新しい差分があればPush通知も飛ぶ（`notifiedKeys`で定期実行と重複しない）
- `MODEL_PRICE_WATCH_ENABLED` は定期実行の判定だけで、手動更新はローカル開発でも公式ページへ取りにいく

## 取得元

| 提供元 | 取得元 | 読むもの |
| --- | --- | --- |
| Anthropic | `platform.claude.com/docs/en/about-claude/pricing.md` | `## Model pricing` の標準API価格（入力・5分キャッシュ書き込み・キャッシュ読み出し・出力） |
| Anthropic | `platform.claude.com/docs/en/models/overview.md` | 表示名 → APIのモデルID（料金表にはIDが無い） |
| OpenAI | `developers.openai.com/api/docs/pricing.md` | `### Standard pricing data` の短文脈の入力・キャッシュ読み出し・キャッシュ書き込み・出力 |
| TypeSafe | なし | 公開の単価ページが無いため「対象外」と理由を記録する（失敗にはしない） |

**公式のAPIに単価は無い**（モデル一覧APIは価格を返さない）ため、ドキュメントの表を読む。

- OpenAIは節見出しで表を選ぶ（Batch・Flex・Fast・Ultrafastは同じ列構成の別の節で、列見出しでは区別できない）。
  節が無い・列見出しが違うときは失敗にする。`-` は「その課金なし」で、0にしない。長文脈の列と、
  `(<272K context length)` のような条件付きの行は通常価格として取り込まない。
- Anthropicの表示名からIDを確かめられないモデルは、IDを推測せず「ID未確定」の候補にする。
- 提供終了のモデルは追加候補にしない。
- ChatGPT・Codex内だけで使えるモデル（公開API単価が無いもの）は料金表に載らないため対象外。

## 結果の区分

- **変更なし / 更新候補あり / 一部失敗 / 失敗**を区別する。取得失敗・解析失敗は「変更なし」にならず、
  既存の単価表と前回の候補はそのまま保持する（失敗した提供元は前回の候補を持ち越して表示する）。
- 候補の区分: **追加**（公式にあって単価表に無い。未使用のモデルも含む）・**価格変更**・**出典確認**
  （「出典未確認」の単価が公式と一致した）・**掲載終了**（情報のみ。通知しない）。
- 異常の確認手段: 単価表の「定期チェック」の結果表示と、失敗のPush通知。ホストのsystemdタイマーを集計する
  「定期ジョブ」の監視には載らない（VPS内のタイマーのため。#497で承認済み）。

## 通知

- 新しい差分（差分キー = 区分・提供元・モデル・公式の単価）を1回だけ通知する。**価格がさらに変わると別の差分**として
  再び通知する。失敗も同じ内容が続く間は1回だけ。
- 宛先は `sendPushWhere` + `isHostAlertRecipient`（いまアクセスが許可されている利用者・端末の
  「ホスト・監視の障害通知」がオンのもの）。`sendPushToAll` は使わない（#489以降、取り消した利用者にも届くため）。
- 1台にも届かなかった通知は記録せず、次の実行で送り直す。

## 画面からの反映・非表示（#566）

単価表のモーダルから、候補の反映・非表示と、登録済みモデルの非表示ができる（`POST /api/model-price-watch/actions`。セッション＋CSRF）。
状態は `.data/model-price-overrides.json`（`MODEL_PRICE_OVERRIDES_PATH` で差し替え可）にだけ持ち、`models.ts` のコードは書き換えない。

- **反映**: 候補のキーからサーバーが保存済みの候補を引き、公式の単価（`-` は0）で `added` に登録する。`models.ts` の一覧へ重ねられ
  （同じIDは置き換え）、`findModel`・`estimateCostUsd` も同じ一覧を引く。ID未確定・通常価格なし・掲載終了の候補は反映できない。
  `models.ts` は同期の取得関数（`setExtraModelsProvider`）だけを持ち、`overrides.ts` がmtimeを見て読み直す（クライアントには差し込まれない）
- **非表示（候補）**: 候補のキー（区分・提供元・モデル・公式単価）で隠す。価格が変わると別のキーになり再び出る。隠した候補はPush通知の対象外
- **非表示（モデル）**: 表示だけの印。一覧・金額の計算には残す（消すと過去期間の金額が「不明」になる。#418）
- 画面のAI利用タブの名前・色は、反映したモデルについてはID表示・既定色のまま（金額はサーバー側で計算される）

## 更新候補を単価表へ反映する手順（コードで直す場合）

1. 単価表の「定期チェック」で候補を確認し、出典URLの公式ページで値を目視で確かめる。
2. 出典付きの更新Issueを起票する（モデルID・変更前後・出典URL・確認日を書く）。
3. `models.ts` を直す。**旧モデルの行は消さない**（連携先は期間の途中でモデルを切り替えるため、消すとその期間の金額が「不明」になる）。
   「出典未確認」は公式と一致を確かめたら注記を外す。ID未確定の候補は、公式のモデル概要でIDを確かめてから登録する。
4. 価格を変えた場合の影響: 使用量の概算金額は**過去の期間も新しい単価で再計算される**（単価表のキーで引くだけで、
   期間ごとの単価履歴は持たない）。概算であり確定した請求額ではない。過去の期間の見え方を変えたくない場合は、
   旧単価を別のモデルIDの行として残す案を検討する（別Issue）。
5. 定額枠のAPI価格換算（GPT-5.6系）は実際の請求額ではない（画面の注記は #566 で外した）。

## 本番での実行確認（デプロイ後にユーザーが行う）

PRのマージだけでは運用開始済みにならない。デプロイ後に次を確認する。

1. 起動後すぐ（今週の予定時刻を過ぎていれば）初回が走る。単価表の「定期チェック」に最終チェック日時と結果が出ること。
2. `.data/model-price-watch.json` の `lastRun.providers` が Anthropic・OpenAI とも `ok`、TypeSafe が `unavailable` であること。
3. 初回は未登録の旧モデルが多く追加候補に出る。通知が1回だけ届き、再起動しても同じ差分が再通知されないこと。
4. 次の予定時刻（画面の「次回予定」）以降に、履歴が1件増えていること。
