# ホスト停止・再起動のPush通知と、未解消エラー件数のバッジ（#495）

サブPC・Mac miniなどの受信途絶や再起動、監視の異常を、StatusHubを開いていない間も知らせる。
ホーム画面のPWAアイコンには「現在未解消のエラー件数」を出す（未読通知数ではない）。

## 仕組み

- **判定はVPSのプロセス内で30秒ごと**（`src/instrumentation.ts` → `src/lib/incidents/run.ts`）。画面の表示や
  停止したホストからの次回POSTには依存しない。PM2は fork モード1プロセスなので、プロセス内タイマーで足りる
  （複数プロセスにしたら成り立たない）。`next build` では動かない。
- **停止の閾値は既存のOFFLINE表示と同じ値**（`HOST_STATS_OFFLINE_AFTER_SECONDS`、既定300秒）。判定は
  `judgeHostOnline`（`src/lib/host-stats/store.ts`）の1関数を画面と共有する。
- **再起動は稼働時間の巻き戻りで検知**する（`uptimeSeconds` から「起動時刻の推定」を出し、前回より2分を超えて
  新しくなったとき）。エージェントの変更は不要。正常終了か異常終了かの根拠は無いので「再起動」とだけ表示する。
  初回の観測・受信時刻が前回以前の古い受信では判定しない。
- **状態は `.data/incidents.json` に永続化**する（障害状態・通知履歴・再送待ち・通番 `seq`）。再起動・再デプロイで
  通知を連発しない。受信が途絶えた原因（電源・回線・エージェント）は区別できないので断定しない。

## 通知する出来事

| 出来事 | 通知 |
| --- | --- |
| 受信が閾値を超えて途絶えた | 送る（継続中は繰り返さない） |
| 受信が再開した | 送る（再起動を確認できれば「再起動後」と付く） |
| 途絶えずに稼働時間が巻き戻った | 「再起動」を送る |
| 復旧後に再び途絶えた | 新しい障害として送る |
| サイトDOWN・定期ジョブ・サービス停止の増減 | **送らない**（バッジは次のPushか起動時の同期で合う） |

iOSは通知を出さずにバッジだけを変えるPushを使えず、定期ジョブの異常はSignalyへも通知されているため、Pushは
ホストの停止・復旧・再起動に限っている。**「PWAを閉じたまま復旧するとバッジが減る」のはホストの復旧のとき**で、
それ以外の解消は次のPushかアプリを開いたときの同期で反映される。

送信は成功した（1台以上が受け付けた）ときだけ完了とし、届かなければ30秒〜10分の間隔で再送する（1時間で破棄）。
送信先は、購読の利用者に**いまアクセスが許可されていて**、端末の「ホスト・監視の障害通知」がオンのものだけ。
利用者が未記録の古い購読は、アプリを開いて登録し直されるまで送らない。

## 未解消エラー件数

`GET /api/incidents`（ログインセッションのみ）が返す1つのスナップショットから、PWAバッジを
すべて作る。`seq` は状態が変わるたびに進み、Service Worker と画面が IndexedDB（`status-hub-badge`）に保存した値より
古いPush・応答では件数を巻き戻さない。

| 数えるもの | 既存判定との対応 |
| --- | --- |
| ホスト停止疑い | `online === false`（OFFLINE表示・停止通知と同じ値） |
| サービス停止 | オンラインのホストの `services[].active === false`（ホストカードの停止扱い） |
| 定期ジョブの異常 | `summarizeTimers`（オフラインのホストは除外済み） |
| サイト監視のDOWN | Kuma `down`・UptimeRobot `status >= 8` |

- ホストが停止疑いの間は、配下のサービス・ジョブの古い状態を足さない（ホスト1件にまとめる）
- 同じ対象・同じ原因は1件
- 取得できなかった対象は正常とみなさない。Kuma・UptimeRobotの取得失敗は前回の件数を持ち越し、定期ジョブの
  取得不可とともに「取得できていない対象」へ出す（件数には入れない）。監視の取得は90秒キャッシュする
- 警告・AI利用枠の閾値通知・復旧済みの再起動は数えない。画面を開いただけでは件数は消えない

## 端末側の設定と制約

- ヘッダー右上のメニュー「通知」で、端末ごとにオン/オフ・ホスト障害通知の切り替え・テスト通知ができる。
  許可の要求は利用者の操作（「通知をオンにする」）からのみ
- ヘッダーの未解消エラー一覧ボタンと一覧パネルは#559で削除した（PWAバッジの同期は `useIncidentBadgeSync` が続ける）
- iPhone/iPadは**ホーム画面に追加したアプリ**でのみPush・バッジが使える（iOS 16.4以上）。Safariのタブは非対応。
  端末の「設定 → 通知」でオフにされていたり、集中モードなどで抑止されている間は表示されない
- 通知タップは `/?tab=hosts` を開き、ホストタブを表示する（旧版の `panel=incidents` は無視）
- 購読は登録したログイン利用者に紐づく。他の利用者の端末は解除できない

## 本番反映・実機確認の手順（人手）

1. `HOST_STATS_OFFLINE_AFTER_SECONDS`・`WEB_PUSH_VAPID_*` が本番に設定済みか確認（既存）。追加の環境変数は無い
2. デプロイ後、PM2ログに `[incidents]` のエラーが出ていないこと・`.data/incidents.json` が作られることを確認
3. iPhoneのホーム画面アプリを開き直し（購読が利用者に紐づく）、メニュー「通知」→「テスト通知」が届くこと
4. アプリを閉じた状態でサブPCのエージェントを止める → 約5〜6分後にPushが届き、アイコンのバッジが1になること
5. エージェントを再開 → 復旧のPushが届き、バッジが消えること
6. 短時間の再起動で「再起動」が届くこと（5分以内に再開させる）
